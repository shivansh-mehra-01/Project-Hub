## 1. TRACEABILITY MATRIX LEGEND & CLASSIFICATION RULES

- **VERIFIED:** Fully implemented in backend controller/service, schema, and verified by tests/runtime evidence.
- **PARTIALLY IMPLEMENTED:** Partial implementation exists, but essential user-facing or persisted behavior is incomplete.
- **MISSING:** No functional backend API, database table, or UI workflow exists.
- **UNVERIFIED:** Code or route exists but cannot be verified without unavailable external infrastructure.
- **CONFLICT:** Discrepancy between documentation/expectations and existing implementation.

Every atomic requirement is assigned to a target implementation phase:
- **Phase 1:** System Audit, Discovery & Implementation Blueprint (Current Phase)
- **Phase 2:** Student Identity, Onboarding, Permanent Profile, Dashboard & Navigation
- **Phase 3:** Project Discovery, Idea Management & Project Registration
- **Phase 4:** Smart Team Formation & Team Management
- **Phase 5:** Guide Allocation & Project Initiation
- **Phase 6:** Project Execution, Tasks, Milestones, Logbooks, Collaboration & Contribution Tracking
- **Phase 7:** Deliverables, Vault, Submissions, Faculty Reviews, Viva Defense & Evaluation
- **Phase 8:** Notifications, Academic History, End-to-End Testing, Security Hardening & Acceptance
